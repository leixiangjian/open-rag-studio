知识库系统开发与部署手册

本文档涵盖了从零开始运行本 RAG（检索增强生成）系统的完整步骤。

1. 环境准备

本系统依赖 Python 运行环境、Docker（用于向量数据库）以及 OpenCode 服务端。

1.1 启动 ChromaDB 向量数据库

使用 Docker 运行一个轻量级的 ChromaDB 实例，并开放 8000 端口：

docker run -d --name chromadb -p 8000:8000 chromadb/chroma:latest

1.2 启动 OpenCode 服务

在终端中启动 OpenCode 的本地服务，默认监听 4096 端口：

opencode serve --port 4096

2. 安装依赖与启动后端

系统后端基于 FastAPI 构建，负责解析文档、连接向量库以及调用大模型。

2.1 安装 Python 依赖

打开终端，执行以下命令安装必须的库：

pip install fastapi uvicorn python-multipart httpx chromadb "langchain" "langchain-community" "langchain-chroma" "langchain-huggingface" pypdf docx2txt beautifulsoup4

2.2 启动 FastAPI 后端

将 rag_backend.py 文件保存到本地后，运行以下命令（监听 8001 端口）：

python rag_backend.py
注意：首次运行会自动从 HuggingFace 镜像站下载 BAAI/bge-small-zh-v1.5 嵌入模型（约 100MB），请保持网络通畅。

3. 前端页面访问与配置

直接双击打开 index.html 文件，或者使用静态服务器如 python -m http.server 8080 托管页面。

3.1 配置中心设置

  • OpenCode 连接：点击“测试连接并加载模型”，系统会自动请求 OpenCode 的 /api/model 接口。在下拉框中选择一个免费模型（如 deepseek-v4.1-flash-free），选择后系统会自动下发模型 ID 给后端。
  • 向量库连接：系统默认会自动检测 http://127.0.0.1:8000。若显示绿色“已连接”即可直接使用。

4. 文档导入流程

系统支持 PDF、Word (DOCX) 和纯文本文件的解析与切片。导入向导分为四步：

  1. 选择文档：拖拽或点击上传文件（单文件不超过 20MB）。
  2. 切片配置：默认 Chunk Size 为 800 字符，Overlap 为 150 字符。中文长句较多时，较小的 Chunk Size 通常检索效果更好。
  3. 预览确认：点击后，后端会加载文档并使用 RecursiveCharacterTextSplitter 进行切片，并返回前 5 个片段供确认。
  4. 执行导入：将切片向量化（基于 bge 模型）并写入 ChromaDB 中。

5. 知识库问答 (RAG)

在问答界面，输入问题后，系统运行流程如下：

  • 向量检索：后端将问题向量化，去 ChromaDB 中召回相关度最高的 3 个切片。
  • 构建 Prompt：拼接检索到的资料（Context）以及最近两轮的历史对话。
  • 模型生成：将 Prompt 发送给 OpenCode 绑定的模型，后端截获流式数据后，通过打字机效果在页面逐字展示。

6. 常见问题排查 (FAQ)

Q1: 为什么对话时报错 [OpenCode 错误] HTTP 500？

通常是因为上下文超出了模型的最大 Token 限制，或者 OpenCode 进程异常。系统已经在前后端限制了仅携带最近 2 轮对话。若仍报错，请查看 OpenCode 的终端输出。

Q2: 为什么 ChromaDB 连接测试失败？

检查 ChromaDB 的 8000 端口是否被占用，或 Docker 容器是否正常运行。Chroma 1.x 版本引入了 CORS 限制，但在本系统中，前端探活是走后端（8001）代理的，所以只要后端启动，通常不受浏览器跨域限制。

Q3: 文件导入时提示 "Failed to fetch"？

这说明前端无法连接到 8001 端口的 RAG 后端。请确认终端是否显示了 Uvicorn running on http://127.0.0.1:8001，以及是否因为缺少依赖导致后端启动崩溃。
